# momo-web 项目简介与实现规格

> 这份文档是交给实现方 AI 的主文档。目标是把“今天记不住的词”自动变成一篇**可朗读、可挖空、可做题**的考研风格英语短文。

---

## 1. 一句话定义

用户粘贴自己的墨墨开放 API Token，网站读取当天标记为「忘记 / 模糊」的单词，再调用用户自己的 OpenAI 兼容模型，生成一篇模仿考研英语文体的巩固短文，附中文译文、逐词释义、记忆提示和阅读理解题。

---

## 2. 背景与问题

墨墨背单词的复习列表只提供“哪些词没记住”，不提供语篇。孤立复习单词有三个问题：

1. **缺少语境**：词义记住了，搭配和用法仍然不会。
2. **缺少复现**：当天错的词，第二天可能继续错。
3. **缺少输出**：只做选择题，不朗读、不造句、不阅读。

把错词组织成一篇连贯文章，可以同时练：

- 词义与词性
- 固定搭配与语篇衔接
- 长难句阅读
- 朗读与复述
- 通过阅读理解题检验理解

直接用大模型生成又容易出现三个质量问题：漏词、生硬堆砌、文体不像考研。所以本项目必须做**取词 → 生成 → 校验 → 复习**的闭环。

---

## 3. 目标用户与使用场景

**核心用户**：正在准备考研英语、同时使用墨墨背单词的中文母语学习者。

**典型场景**：

- 晚上复习完，打开网页，花 1 分钟生成一篇包含今天所有错词的文章，读两遍再睡。
- 第二天早上用“挖空模式”自测，做 5 道阅读题。
- 周末把一周的文章导出成 Markdown，集中复盘。
- 用户有自己的 DeepSeek / OpenAI / Kimi / 本地 Ollama，希望用自己的 Key，而不是被绑定到某个服务。

**非目标用户**：

- 想批量刷复习、自动养号的人（API 也不支持提交复习结果）。
- 想要公共词库、社区分享、内容平台的人。

---

## 4. 核心用户流程

```
打开网页
  ↓
粘贴墨墨 Token（localStorage 保存）
  ↓
POST /api/today → 今日学习记录
  ↓
按 first_response 筛出 FORGET / VAGUE
  ↓
勾选单词（默认全选）
  ↓
选择文体：考研阅读 / 考研完形 / 考研写作 / 外刊 / 故事
  ↓
点击生成
  ↓
（可选）调用用户配置的 OpenAI 兼容模型
  ↓
校验：目标词是否全部出现、词数、JSON 结构
  ↓
展示：文章 + 译文 + 词汇卡 + 阅读题
  ↓
挖空自测 / 显示译文 / 做题 / 复制 / 下载 / 打印
```

## 5. 功能范围

### 5.1 MVP（必须做）

- Token 输入、保存、清除、有效性校验。
- 拉取今日学习记录，展示 `FORGET` / `VAGUE` 数量和词表。
- 按反馈类型筛选；单词可逐个勾选/取消。
- 手动粘贴单词（无 Token 或想练额外词表时使用）。
- 选择文体、难度、长度。
- 调用 OpenAI 兼容模型生成：
  - 英文短文
  - 中文译文
  - 逐词中文释义 + 记忆提示
  - 5 道阅读理解单选题（可关闭）
- 生成结果校验与失败回退。
- 文章阅读：目标词高亮、点击查看释义。
- 挖空模式：隐藏目标词，点击逐个揭示。
- 中文译文显示/隐藏。
- 复制 Markdown、下载 `.md`、打印。
- 桌面与移动端响应式。
- 完整的错误提示：401、429、空数据、模型超时、JSON 解析失败。

### 5.2 P1（应该做）

- 多篇分段：超过 15 个词时自动拆成多篇，保持同一文体。
- 生成历史：最近 7 天保存在 IndexedDB，可回看。
- 阅读题交互：点选项即时判对错，显示解析。
- 朗读：浏览器 `SpeechSynthesis` 朗读英文正文。
- 词表导出 CSV；文章导出带日期的 Markdown。
- 深色模式（跟随系统）。
- “只练忘记” / “忘记 + 模糊” 快捷筛选。

### 5.3 P2（可选）

- 回写墨墨：把生成的例句/助记/释义写回账号（注意每天 600 条上限）。
- 生成 Markji 卡片：使用 `[F#1#...]`、`[Choice#...]`、`[E##...]` 语法批量制卡。
- 学习数据看板：今日完成率、学习时长、未来 7 天复习量。
- 多用户部署：账号体系、Token 加密存储、按用户隔离。
- 语音评测、跟读打分。

### 5.4 明确不做

- 自动提交复习结果（API 没有写接口，也不符合平台规则）。
- 抓包、逆向、爬取 App 数据。
- 公共词库、社区、内容分发。
- 复制考研真题或外刊原文。

## 6. 技术架构

### 6.1 方案 A：本地优先（推荐 MVP）

```
浏览器（静态页面）
   │  同源请求
   ▼
本地 Python 服务 127.0.0.1:8765
   ├─ GET  /            静态文件
   ├─ POST /api/today   → 墨墨开放 API
   ├─ POST /api/generate→ 用户配置的 LLM
   └─ POST /api/llm-test→ 连通性测试
```

特点：

- 只用 Python 标准库，`python server.py` 即可启动，无 pip 依赖。
- 没有 CORS 问题：浏览器只和 localhost 同源通信。
- Token 和 API Key 只在浏览器与本地服务之间传递，不经过第三方。
- 不需要域名、服务器、数据库。
- 适合个人使用，成本为 0。

### 6.2 方案 B：公开部署（可选）

```
浏览器（静态页）
   │  同源
   ▼
Serverless Function（Cloudflare Worker / Vercel Function）
   ├─ /api/today    → 墨墨 API
   └─ /api/generate → 用户 LLM
```

必须遵守：

- **每个用户使用自己的 Token**，不要把一枚 Token 共享给所有访客。
- Token 只存在浏览器内存或 localStorage，按请求透传，服务端不落库、不写日志。
- 加 IP 级限流，防止被当成免费代理。
- 不提供账号体系时，不做服务端生成历史。

**纯静态托管不可行**：墨墨 API 没有 CORS 头，浏览器直连会被拦截。GitHub Pages、纯静态 Vercel/Netlify 只能托管页面，必须额外配 serverless 代理。

### 6.3 数据存储

| 数据 | 位置 | 说明 |
|---|---|---|
| 墨墨 Token | `localStorage` | 用户可一键清除 |
| LLM 配置（base_url / key / model） | `localStorage` | Key 仅本地 |
| 今日词表 | 内存 | 刷新后重新拉取 |
| 生成结果 | 内存 + 可选 IndexedDB | 不传服务端 |
| 服务端日志 | 不记录 Token/Key | 只记录方法、路径、状态码 |

## 7. 墨墨 API 契约

完整调研见 [API-NOTES.md](API-NOTES.md)。实现只需要关注下面这些。

### 7.1 拉取今日词

```http
POST https://open.maimemo.com/open/api/v1/memo/study/get_today_items
Authorization: Bearer <token>
Content-Type: application/json

{ "limit": 1000 }
```

响应（节选）：

```json
{
  "today_items": [
    {
      "voc_id": "abc",
      "voc_spelling": "ambiguous",
      "order": 12,
      "first_response": "VAGUE",
      "is_new": false,
      "is_finished": true
    }
  ]
}
```

前端映射：

```ts
type WordItem = {
  id: string
  spelling: string
  order: number
  response: 'FORGET' | 'VAGUE' | 'FAMILIAR' | 'WELL_FAMILIAR' | 'CANCEL_WELL_FAMILIAR'
  isNew: boolean
  isFinished: boolean
}
```

筛选规则：

- 默认只显示 `FORGET` 和 `VAGUE`。
- 只保留 `first_response` 非空的条目。
- 按 `order` 升序。
- 按拼写去重（大小写不敏感）。

错误处理：

| 状态 | 提示 |
|---|---|
| 401 | Token 无效或过期，请重新获取 |
| 429 | 请求过于频繁，请稍后再试 |
| 空数组 | 今天没有学习记录；检查自动同步和当天是否打开过 App |
| 网络错误 | 无法连接墨墨服务，请检查网络 |

### 7.2 频控与缓存

- 读接口：10 秒 20 次、60 秒 40 次、5 小时 2000 次。
- 一次拉取最多返回 1000 条，个人使用一天一次足够。
- 页面加载时最多自动拉取一次；提供手动刷新按钮；不要轮询。
- 生成文章不消耗墨墨频控，只消耗用户自己的模型额度。

### 7.3 不能做的事

- 不能读别人的释义/助记/例句。
- 不能新建/删除牌组、章节、卡片。
- 不能提交复习结果。
- 单词接口没有释义、音标、发音。

## 8. AI 生成设计

### 8.1 模型接入

支持任意 OpenAI 兼容接口：

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-...",
  "model": "deepseek-chat"
}
```

地址规范化规则：

- 以 `/chat/completions` 结尾：直接使用。
- 以 `/v1`、`/v4`、`/api/paas/v4`、`/compatible-mode/v1` 结尾：追加 `/chat/completions`。
- 以 `/openai` 结尾（Gemini 兼容层）：追加 `/chat/completions`。
- 其他：追加 `/v1/chat/completions`。

常见预设：

| 服务 | Base URL | 模型示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |

### 8.2 分批策略

- 每篇最多 15 个目标词。
- 超过 15 个自动拆分，顺序生成，输出“第 1/3 篇”。
- 每篇独立包含标题、正文、译文、词汇、题目。
- 同一批次使用相同文体、难度和长度，避免风格跳变。

### 8.3 提示词模板（考研阅读）

```text
你是一位考研英语命题与教学专家。请用下面这些单词写一篇考研英语阅读理解 Part A 风格的短文。

目标单词（必须全部自然出现，可改变词形）：
- ambiguous（今天标记：模糊）
- deteriorate（今天标记：忘记）
...

文体要求：
1. 题材：外刊式的社科、教育、科技或环境评论。
2. 4-5 段，约 420 词。首段引出争议或现象；中段展开论证并呈现不同立场；末段收束或提出建议。
3. 正式书面语，使用复杂句、指代、衔接词和必要的限定语；避免对话、口语和生硬堆砌。
4. 每个目标词至少出现一次，并在文中用 **单词** 加粗。
5. 不要照抄任何考研真题或外刊原文，只模仿文体。
6. 另写一份自然的中文译文，译文中对应的词也用 **加粗** 标出。
7. 为每个目标词给出：结合文中用法的中文释义（10-20 字）、一个简短的中文记忆提示。
8. 另出 5 道阅读理解单选题：题干和选项用英文，答案为 A/B/C/D，解析用中文。
   考查主旨、细节、推断、词义和作者态度，不要考语法。

只输出一个 JSON 对象，不要 Markdown 代码块：
{
  "title_en": "...",
  "article_en": "...",
  "title_zh": "...",
  "article_zh": "...",
  "glossary": [
    { "word": "...", "meaning_zh": "...", "tip_zh": "..." }
  ],
  "quiz": [
    {
      "question": "...",
      "options": { "A": "...", "B": "...", "C": "...", "D": "..." },
      "answer": "A",
      "explanation_zh": "..."
    }
  ]
}
```

### 8.4 考研文体的可执行标准

不要只写“像考研”。实现时按下面的检查表约束模型：

| 维度 | 要求 |
|---|---|
| 题材 | 社会科学、教育、科技、环境、商业、心理；避免纯文学和日记 |
| 结构 | 4-5 段；现象/争议 → 论证 → 反方或限定 → 结论/建议 |
| 句法 | 至少 30% 的句子含从句、非谓语或插入语；避免全是简单句 |
| 衔接 | 使用 however、while、rather than、in so far as、by contrast 等逻辑连接 |
| 语气 | 正式、克制、有 hedge（may、tend to、it is argued that） |
| 词汇 | 允许学术词和抽象名词，但目标词必须自然出现，不能为了用词而扭曲语义 |
| 反模板 | 避免 "With the development of society"、"Every coin has two sides" 等陈词 |
| 版权 | 只模仿文体，不复制真题、外刊原文或受版权保护的段落 |

考研完形：

- 250-320 词，记叙与说明结合，逻辑衔接紧密。
- 句子长度适中，适合挖空。
- 不要求出题，但可以标记适合挖空的词。

考研写作：

- 160-220 词，三段式：描述现象/图画 → 分析原因 → 提出建议。
- 正式、有观点、有衔接；避免空洞模板句。
- 可附中文提纲。

### 8.5 输出校验（必须实现）

生成后不要直接渲染。依次检查：

1. **JSON 可解析**：去掉 ```json 代码块，失败时尝试提取第一个 `{...}`。
2. **正文非空**：`article_en` 至少 80 词。
3. **词数**：目标长度 ±25%。
4. **目标词覆盖**：每个目标词至少出现一次（大小写不敏感，允许常见词形变化：`s/es/ed/d/ing/ly`）。漏词则触发一次修复重试。
5. **无中文混入**：`article_en` 中不应出现大段中文。
6. **译文对应**：`article_zh` 非空且长度合理。
7. **词汇表覆盖**：`glossary` 覆盖全部目标词；缺失的用模型补一次，或在前端标注。
8. **题目合法**：每题 4 个选项，`answer` 在 A-D 内，解析非空。

修复重试提示词：

```text
上一版文章漏掉了这些目标词：<list>。
请在不改变原有情节和结构的前提下改写文章，确保每个词至少自然出现一次，
仍然用 **单词** 加粗，并重新输出完整 JSON。
```

失败策略：

- 单篇重试 1 次。
- 仍失败：展示本地串联稿，并明确标注“AI 生成失败，已回退”。
- 不要静默丢失用户已选的词。

### 8.6 本地兜底稿

没有配置模型，或模型调用失败时，生成一篇“复习日记”式短文：

- 包含全部目标词，每个词用 `**加粗**`。
- 内容是按固定句式串联的反思性短文，不提供词义和译文。
- 明确标注“本地串联稿”，提示配置 AI 后可获得语义更连贯的文章。
- 挖空和复制/下载仍然可用。

### 8.7 成本估算

一篇 420 词文章 + 译文 + 词汇 + 5 题，输出约 2,000-3,000 tokens。

- DeepSeek：约 ¥0.01-0.03 / 篇。
- GPT-4o-mini：约 $0.002-0.005 / 篇。
- 本地 Ollama：0 元，取决于机器。

每天 15 个词以内，一个月成本通常低于一杯咖啡。

## 9. UI / UX

### 9.1 布局

- 桌面：左侧 360px 操作栏，右侧文章阅读区。
- 移动：单列，操作栏在上，文章在下。
- 阅读区使用纸张质感、衬线字体、宽松行距，接近杂志排版。
- 目标词用黄色底纹高亮，点击滚动到词汇卡。

### 9.2 关键状态

| 状态 | 表现 |
|---|---|
| 未连接 | 空状态：说明三步流程 + Token 获取链接 |
| 加载中 | 按钮禁用 + 细进度条 |
| 401 | 输入框下方红色提示 + 重新获取链接 |
| 今日无数据 | 黄色提示条：检查自动同步/当天打开 App |
| 无错词 | 提示可手动粘贴单词 |
| 生成中 | 按钮“正在织…” + 进度条；多篇时显示第几篇 |
| AI 失败 | 黄色提示条 + 已回退本地稿 |
| 模型未按 JSON 返回 | 尽量展示正文，并提示译文/词汇可能缺失 |

### 9.3 交互细节

- `Ctrl/Cmd + Enter` 生成。
- 挖空模式下点击空格揭示；再次关闭挖空恢复全文。
- 阅读题点选项即时判对错，显示解析。
- 复制内容为 Markdown；下载文件名带日期。
- 打印时隐藏操作栏，只保留文章、译文、词汇和题目。

### 9.4 可访问性

- 键盘可操作所有按钮和输入框。
- 焦点样式清晰。
- 颜色对比度达到 WCAG AA。
- 尊重 `prefers-reduced-motion`。
- 文章使用语义化 `article`、`h1`、`p`。

## 10. 安全与隐私

**必须**：

- Token 和 API Key 不写入日志、数据库、仓库、分析服务。
- 本地服务默认只监听 `127.0.0.1`。
- 公开部署时，服务端只做透传，不持久化凭证。
- 限制请求体大小，防止滥用。
- 前端渲染模型输出前必须转义 HTML，禁止 `innerHTML` 直接插入未转义内容。
- 只使用官方 API，不抓包、不逆向。

**建议**：

- 提供“清除 Token / 清除 AI 配置”按钮。
- 在 UI 明确说明 Token 的权限范围。
- 公开部署加 IP 限流和 CORS 白名单。

## 11. 验收标准

### 11.1 功能

- [ ] 输入有效 Token，能看到今日学习记录和错词数量。
- [ ] 输入无效 Token，显示可读的 401 提示。
- [ ] 今日无数据时，显示自动同步/打开 App 的提示。
- [ ] 可以只保留 `FORGET`、只保留 `VAGUE`，或两者都保留。
- [ ] 手动粘贴 20 个单词，能直接生成文章。
- [ ] 配置 DeepSeek/OpenAI/Ollama 后，能生成文章、译文、词汇和 5 道题。
- [ ] 文章包含全部目标词；漏词时自动重试一次。
- [ ] 未配置模型时，回退到本地串联稿，并明确标注。

## 13. 风险与开放问题

### 风险

1. **公测接口不稳定**：`/memo/study/*` 标注为公测，字段和行为可能调整。需要把响应解析写得宽松，并提供降级提示。
2. **模型漏词**：必须程序化校验；不能只依赖提示词。
3. **JSON 不稳定**：部分模型会加代码块或解释，需要容错解析和重试。
4. **版权**：只模仿文体，不复制真题/外刊原文；提示词中明确禁止。
5. **公开部署的凭证风险**：多用户场景下，Token 泄露是最大风险。默认只做本地版。
6. **频控**：不要轮询；缓存今日结果；一次拉取 1000 条足够。
7. **模型成本**：长文 + 题目会增加输出 token；提供“短/中/长”和“是否出题”开关。

### 开放问题（需要产品决策）

- 只做本地版，还是一开始就做公开部署？
- 默认模型选哪个？DeepSeek 性价比高，Ollama 完全免费但质量取决于本地模型。
- 是否需要把生成内容回写墨墨（例句/助记/释义）？涉及每天 600 条上限和内容质量。
- 是否需要生成 Markji 卡片？如果需要，卡片语法和文件上传要单独设计。
- 是否需要账号体系和历史记录？如果需要公开部署，必须做 Token 加密和用户隔离。
- 是否要支持英语二、雅思、托福的独立文体预设？

## 14. 给实现方 AI 的第一步

1. 读 [API-NOTES.md](API-NOTES.md)，确认接口和限制。
2. 先实现 M0：本地 Python 服务 + 静态页 + `/api/today` 代理。

5. 再接模型，按第 8.5 节做校验和重试。
6. 最后做考研题型、挖空、导出和移动端。

**不要**在第一步就做账号、数据库、公共部署。先把本地闭环跑通。
